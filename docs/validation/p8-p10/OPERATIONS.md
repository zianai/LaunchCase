# LaunchCase controlled local operation

The selected topology is **one host**: independent LaunchCase business SQLite, immutable objects and LangGraph SQLite checkpoint in a private data directory; TaskManager owns leases and fencing. CreativeEngine runs as a separate trusted loopback/token service. A graph checkpoint is a cursor, never authority for a human gate. PostgreSQL/Redis are optional historical adapters; the P8–P10 optional container probe failed readiness and does not establish multi-host support. No public deployment is authorized.

Use Python 3.12 and the frozen uv.lock; `uv sync --frozen --extra dev`; `npm ci --prefix frontend`; `npm run build --prefix frontend`. Dependencies must come from the lock. The independent consumer check is `.venv/bin/python -m pytest tests/test_ce_contract.py -q`, with no CE source checkout. Local compatibility drills require an explicitly selected CE checkout and use process/HTTP boundaries: `.venv/bin/python ops/verify_p8_p10_stack.py --engine-repo /absolute/path/to/creative-engine --out /new/evidence/directory`. Add `--ui` for the original-image flow; `--suite handoff` or `--suite regression` selects existing browser regressions. The drills inherit only PATH/HOME/TMPDIR/browser-cache and bind numeric loopback; use an OS egress policy when executing them.

For controlled single-host staging, copy `ops/staging.env.example` to a private operator-controlled environment **outside Git**, replace the data path, migrate via `launchcase init-db`, provision a tenant owner with `launchcase auth create --tenant <id> --name <name> --role owner --synthetic` for E1, and save the returned token in a mode-0600 file. Do not put tokens in URLs, tickets or screenshots. Start `uvicorn launchcase.api:app --host 127.0.0.1 --port 8815` and the built frontend with `node node_modules/next/dist/bin/next start --hostname 127.0.0.1 --port 3315`. CE credentials stay in backend configuration; the browser only receives its HttpOnly local identity cookie. Existing real identities/data require separate authorization and are not loaded by these drills.

Check `/health` and `launchcase doctor`, then authenticated `GET /api/v1/operations/status` (or `launchcase operations-status`). Only a human tenant owner may view that tenant's queue/failure/expired-lease/reconciling/awaiting-review counts. Alert on failed tasks, expired leases and reconciling visuals. Review queued task ages and awaiting-asset-review counts before accepting more work. Unknown receipts/costs must be reconciled by the exact request/plan hash: do not resubmit to clear an alert. This release only accepts explicit zero-cost CE receipts; null/missing/nonfinite/nonzero amounts are rejected. Paid usage, provider bills and production service-level targets remain unmeasured.

Token rotation: authenticated owner runs `launchcase rotate-token --identity <id> --out /new/private/token-file`. The file is created exclusively with mode 0600; no replacement token is printed. `--revoke-only` invalidates the old token and discards the replacement. Reauthenticate the browser after rotation. Tenant mismatch and non-owner roles are rejected. An operator must retain a second owner recovery credential before rotating the sole active owner.

Backup: stop API/workers and wait for known remote submissions to settle; preserve unresolved receipt liabilities. Run `launchcase backup --out /new/private/backup`, then verify `backup-manifest.json` hashes and store a separate protected copy. Failure is an operational alert; never label an incomplete backup healthy. Restore with `launchcase restore --source /private/backup --out /new/private/restore`, point settings at that new directory, and run `launchcase init-db`. Inspect case, immutable source/asset hashes, decisions, task status and current handoff before resuming. Roll back via the untouched backup into another new directory; never downgrade a production database in place. `ops/verify_p10_recovery.py` demonstrates this on synthetic data and reports measured local timing only, with production RTO/RPO null.

Retention: `launchcase retention` is a tenant-owner dry run; `--confirm-tenant <exact-id>` is destructive and requires separately bounded operator authorization for real data. Active queued/running tasks or unknown remote receipts block deletion. Existing code clears tenant DB rows, unreferenced objects, checkpoint threads and local Mock receipts; external CE data, exported files and backups need separate authorized retention. Use the dry run to inspect scope; do not infer deletion approval from a pilot report.

HTTPS, externally reachable authentication, secret-store integration, public egress, scheduled backup monitoring, real operating load, multi-host consistency and production deployment are external prerequisites. They are not activated by the local template. Browser screenshots demonstrate runtime behavior, not human design approval.
